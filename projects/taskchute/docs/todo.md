# Taskchute User Stories

## 完了

### US-001 ✅ 計画タスクをセクション欄から直接入力したい

**ユーザーとして** 朝/昼/夜の各セクションに対して、その場で計画タスクを書き込み追加したい。
**なぜなら** 上部フォームで「セクションを選択して追加」する流れは、計画を立てる思考の流れに対して操作が多すぎるから。

---

## いますぐ開始フロー

> 計画用の下部セクション入力と役割分担し、上部フォームを「いま始めるものを記録する」専用に組み替える。

### US-002 思いついた瞬間にタスクを開始したい

**ユーザーとして** 「いま始める」と決めた作業を、ワンアクションで記録開始したい。
**なぜなら** 計画にない突発タスクが発生したとき、フォームの細かい入力に意識を取られると実行に入る摩擦が増えるから。「あとで何時から何をやる」を作るのが下部のセクション入力、「いま始めるものを記録する」のが上部、と役割を完全に分けたい。

**受け入れ条件**
- [ ] ボタン1つで「作成 + 即開始」が完了する
- [ ] 開始時刻は操作時点の現在時刻で確定する（事前に選ぶ余地なし。後から修正は **US-005**）
- [ ] 上部フォームから「セクション選択」「見積分」「+ 追加」を撤去する
- [ ] 残すのは「タイトル入力（任意）」と「いま開始」ボタンの2要素のみ
- [ ] 既に進行中タスクがある場合は自動終了 → 新規開始する（TaskChute 的に自然）

**技術メモ**
- バックエンドに `POST /tasks/start_now` を追加して1リクエスト化する（現状は `POST /tasks` → `POST /tasks/:id/start` の2段）
- 見積分は未設定（モデルデフォルト `0`）で作成。`0` のままで差分計算が壊れないことを確認する
- UI: `app/javascript/components/TaskForm.tsx` を簡素化
- スタイル: `TaskForm.module.css` のグリッドを `1fr auto` 程度に再構成

---

### US-003 タイトル未入力でもタスクを始めたい

**ユーザーとして** タイトルを考える前に作業を始めたい瞬間でも、開始操作を止めずに記録したい。命名は後でいい。
**なぜなら** 「タイトルを考える」が開始の摩擦になると、結局記録しなくなって TaskChute の意味が薄れるから。

**受け入れ条件**
- [ ] タイトル空のまま「いま開始」できる
- [ ] 仮タイトル（例: `無題のタスク`）で保存され、TaskRow のインライン編集で後から命名できる

**技術メモ**
- Task モデルに `validates :title, presence: true` があるため、空文字ではなく仮タイトルを自動代入する方針
- **US-002** に内包される。単独で残す場合は、セクション末尾入力欄でもタイトル空送信を許容するか別途判断

---

### US-004 開始セクションを現在時刻から自動判定してほしい

**ユーザーとして** いますぐ開始するタスクが朝/昼/夜のどこに入るかを、毎回選びたくない。
**なぜなら** いま開始するタスクのセクションは時刻を見れば自明だから。

**受け入れ条件**
- [ ] 現在時刻からセクションを自動決定する
- [ ] 境界値の例: `04:00–10:59 = morning` / `11:00–16:59 = noon` / それ以外 `= night`（要決定）

**スコープ外**
- 境界値をユーザー設定可能にするのは v1 ではやらない

## タスク時刻の事後修正

### US-005 タスクの開始時刻を後から修正したい

**ユーザーとして** 「実は10分前に始めていた」「いま開始ボタンを押し忘れていた」というケースで、開始時刻を遡って修正したい。
**なぜなら** **US-002** では開始時刻が「ボタンを押した瞬間」に固定されるので、現実とのズレを補正する手段が必須だから。

**受け入れ条件**
- [ ] TaskRow から `started_at` を編集できる（time input または時刻ピッカー）
- [ ] 修正内容が即座に保存される

**技術メモ**
- `PATCH /tasks/:id` の許可パラメータに `started_at` を追加（`app/controllers/tasks_controller.rb#task_params`）

---

### US-006 タスクの終了時刻を後から修正したい

**ユーザーとして** 終了ボタンを押し忘れて時間が伸びてしまった、または早めに終わっていたケースで、終了時刻を修正したい。
**なぜなら** 実績時間（`actual_minutes`）が現実と合っていないと、振り返りや見積精度の改善が機能しないから。

**受け入れ条件**
- [ ] TaskRow から `finished_at` を編集できる
- [ ] 終了時刻が変わると `actual_minutes` も連動して更新される
- [ ] 終了時刻 < 開始時刻 は保存できない（バリデーションエラー）

**技術メモ**
- `task_params` に `finished_at` を追加
- `actual_minutes` は `started_at` と `finished_at` の差から算出されるため追加実装不要
- 終了時刻 < 開始時刻 のバリデーションを Task モデルに追加
